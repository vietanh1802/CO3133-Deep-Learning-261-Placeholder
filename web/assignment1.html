Assignment 1

Image classification

Comparing image classifiers on MNIST, Fashion-MNIST, and CIFAR-10.

Problem statement

How does model architecture affect accuracy, learning behavior, and mistakes across different image datasets? We compare Linear, MLP, CNN, GRU, LSTM, and Transformer models on MNIST, Fashion-MNIST, and CIFAR-10. Each model trains for 50 epochs with seed 42.

Dataset and EDA

Class means and prototype similarity motivate inspecting Shirt, Coat, and Pullover recall and confusion. Similar average silhouettes are descriptive evidence about the data; they do not establish that flattening caused an error. The error analysis compares class recall across the models.

Experimental setup

MNIST and Fashion-MNIST use 28-by-28 grayscale images: 54,000 training, 6,000 validation, and 10,000 official test examples. CIFAR-10 uses 32-by-32 color images: 45,000 training, 5,000 validation, and 10,000 official test examples. A seeded random permutation reserves 10% of the official training split for validation; it is not a stratified split.

All runs use Adam, cross-entropy from logits, learning rate 0.001, batch size 128, and 50 epochs. Grayscale training uses random affine augmentation and normalization with mean/std 0.5. CIFAR-10 training uses random crops and horizontal flips, with per-channel mean (0.4914, 0.4822, 0.4465) and standard deviation (0.2470, 0.2435, 0.2616). Validation and test transforms are deterministic, with no augmentation. Each model uses its lowest-validation-loss checkpoint.

Linear and MLP flatten the image; MLP adds hidden layers of 256 and 128 units with ReLU and dropout 0.2. CNN uses two convolution blocks with 32 and 64 channels, batch normalization, max pooling, then flattens the feature maps into a 128-unit ReLU layer. GRU and LSTM scan image rows with 128-unit recurrent cells. Transformer projects image rows to 128-dimensional tokens, adds sinusoidal positions, and uses two attention layers with four heads. Every encoder feeds a ten-class head.

Learning curves

MNIST

CNN has the lowest validation loss among the evaluated models (0.0170, epoch 34). Its final training and validation losses are 0.0160 and 0.0195. Test predictions use the checkpoint with the lowest validation loss.

Fashion-MNIST

CNN has the lowest validation loss among the evaluated models (0.1948, epoch 42). Its final training and validation losses are 0.1765 and 0.1957. Test predictions use the checkpoint with the lowest validation loss.

CIFAR-10

Transformer has the lowest validation loss among the evaluated models (0.9063, epoch 30). Its final training and validation losses are 0.5225 and 1.0668. Test predictions use the checkpoint with the lowest validation loss.

CIFAR-10 Transformer validation loss reaches its minimum at epoch 30 and then rises while training loss continues downward, consistent with overfitting in this run. Training loss can exceed validation loss because training applies augmentation and dropout; that gap alone does not diagnose underfitting.

Discussion

On MNIST, CNN reaches 99.41%, Transformer 99.31%, LSTM 99.27%, GRU 99.24%, MLP 98.45%, Linear 85.68%. These results describe one seed and the configurations listed above.

On Fashion-MNIST, CNN reaches 92.59%, Transformer 90.43%, GRU 89.88%, LSTM 89.52%, MLP 87.18%, Linear 77.05%. These results describe one seed and the configurations listed above.

On CIFAR-10, Transformer reaches 68.71%, LSTM 64.42%, GRU 64.24%, MLP 47.67%, Linear 35.27%. These results describe one seed and the configurations listed above.

Parameter count measures model size. The runs do not share a verified hardware and timing protocol, so these results do not support a speed ranking.

Limitations and reproduction

These are single-seed observations with fixed configurations. Architecture, parameter count, augmentation response, and optimization behavior vary together; the study does not isolate a causal architectural effect or estimate variability across seeds. MNIST is a development dataset. These comparisons use six architectures and one seed. They do not measure variation across seeds.

Per-run test metrics and error summaries are saved under results/a1/. Evaluation also saves local prediction tensors as test_evidence.pt; these are excluded from Git and must be regenerated from checkpoints. The website uses the run list in runs.json.

Evaluate each dataset with its matching configuration. Each result records the checkpoint, settings, and test metrics.

python -m scripts.evaluation.evaluate --data fashion_mnist --config configs/image_classification/fashion_mnist/cnn.yaml
